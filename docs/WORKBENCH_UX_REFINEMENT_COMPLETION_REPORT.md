## Presentation behavior

The centralized adapter maps machine values such as `INDEPENDENT_ONLY`, `PARTIAL`, `CONFLICTING`, `ADDRESS_AMBIGUOUS`, `SOURCE_STOP` and `DERIVED` to readable display text while preserving the original values in the model and technical details. Missing labels are contextual: tenure/title is “Not independently verified,” condition/repairs is “Not assessed,” and generic fields are “Not available from current evidence.” Zero and false remain explicit values.

Property Mode order is Overview, Valuation, Comps & map, Property Details, Evidence, Sources. It has no Economics, Scenarios, Sensitivity or Questions sections/anchors. Deal Mode adds those sections only when analytical output is present and keeps the existing Create Deal/manual-claims workflow.

Property Details uses only existing `model.property` and evidence values: type, bedrooms, bathrooms, living area, year, lot, APN/parcel, county; latest transaction/assessment/tax summaries with dated expandable records; zoning, legal description and land/ownership status; readable features when supplied. It never invents values or turns unknown into zero.

Evidence is grouped into Identity & Location, Property Characteristics, Valuation & Market, Tax & Assessment, Transaction History and Legal / Ownership / Condition. Comparable properties are represented by an aggregate count in the evidence panel; individual comp facts and provenance remain in the unchanged comp table/map. Technical references are behind “View source details.”

Valuation is one proportional deterministic `LOW — ESTIMATED VALUE — HIGH` scale with padded domain, accessible text, provider-range/estimated-value labels and Deal Mode break-even/resale overlays. It has no probability semantics. Manufactured-home tenure/comparability caution is conditional on subject property type.
